# 任务控制扩展

此 Fork 基于上游 `2ee148985c8ac49069a19d13c5ba93960cd9568e`，保留 MIT 许可证。仅补跨规则任务身份和整体停止；队列、领取、回执、重试、事件日志及进程树中止继续使用原生实现。不包含界面、继续、删除或新的执行器。

## 身份与接口

全部接口仅接受本人密钥，浏览器不持有密钥。调用方先核验真实项目权限；Hub 不另建账号体系。

| 请求 | 合同 |
| --- | --- |
| `POST /v1/tasks` | `{id, project, source, event}`：调用方生成全 Hub 唯一的稳定任务 ID，绑定项目标识、已配置来源和首个原生事件；同 ID 同规范化输入返回原任务，不同输入返回 409 |
| `GET /v1/tasks/{id}` | 返回固定身份、创建与停止时间、`active/stopping/stopped`、所属轮次 ID 和尚未核实结束的轮次 ID |
| `POST /v1/tasks/{id}/events` | 提交后续外部事件，沿用来源的原生事件 ID 去重；不允许复用其他任务或非任务事件的 ID；停止后返回 409 |
| `POST /v1/tasks/{id}/stop` | 空 JSON 对象；原子记录停止意图、取消排队、关闭待确认卡片、移除未到期复查；重复请求读取同一停止结果 |

`id`、`project` 为 1–64 位 ASCII 字母数字、点、下划线或连字符，首位字母数字。事件沿用原生长度与类型验证；任务事件的 subject 固定为任务 ID，调用方不传或必须相同。事件去重仍按来源与事件 ID；中心应给事件 ID 加任务前缀。派生事件的 task_id 从父轮次继承，subject 被归一到任务 ID；模型不能借回执指向另一任务。内部事项使用不能从外部 subject 输入的独立命名空间，不与普通事件合并，即使规则没有 parallel 也不合并不同任务。

任务 ID 与原生 run ID、event ID、card ID 分开；task_id 随事实日志保存，查询与重建使用同一投影。原生状态中的轮次、卡片和复查增加可选 taskId，普通任务不增加此字段。项目标识是可信调用方登记的归属，不由模型正文推断。模板、目录、程序和权限仍只由可信规则配置。本批不支持重开已停止的任务，也不宣称 active 代表业务完成；后续继续应增加新尝试身份并隔离旧回执，不能清空 stop_requested_at。

## 停止与核实

停止和并发回执在原生事实事务中串行裁决。回执先到，停止覆盖其已派生阶段；停止先到，回执仍保留 outcome、summary、error、session 和 usage，但 ask、notice、resolve、later、events 均不生效，不重试。实际成功退出可保留 done，不把已经完成的工作伪造为取消；任务整体为 stopped。

所有 claimed 和 unknown 轮次持续列入原生 Worker 的 cancel 列表；Worker 确认进程树结束后提交原生结果。只要还有其中任一轮次，任务就是 stopping，包括 Worker 离线、漏报执行或重启。只凭超时、缺少心跳、删除规则或收到停止 HTTP 应答不能宣称结束。Worker 丢失本机执行记录时仍等待核实，本批没有强制标记停止入口。

任务使用本 Fork 的配套 Worker：保留原生执行器，修正领取响应同时带取消时不启动、启动前重启先核对停止，以及无法检查进程时保留停止记录继续检查。停止核实先于插件加载；插件失效不能跳过退出核实。取消优先于超时和回执收尾，保留原停止宽限期，不再启动回执修复。未升级的上游 Worker 不能视为已满足完整停止合同。派生事件 ID 与其他任务冲突时仅 rejected 该事件，不拒收整份退出证据。

停止不回滚代码或外部副作用，不清理工作目录。任务之外的事件与规则保持原生行为。后续完整删除必须同时解决事实日志与投影重建、迟到消息及 Worker 独占文件清理，本批不提供假删除。

## 维护与验证

上游为 upstream，本 Fork 为 origin；开发使用 codex/task-stop worktree，不跟随上游未验证的新提交。扩展使用零运行时依赖、原生 HTTP 客户端及事实日志。新增代码注释和提交信息使用简体中文，优先于上游注释语言约定。

回归覆盖排队、执行、重试、卡片、复查、跨规则派生、未知执行、重复停止、身份冲突、错误密钥、重放及原生 Worker 进程树停止。隔离验证只用临时目录、回环接口和虚构任务，不读取正式模型凭据、不调用生产服务。
