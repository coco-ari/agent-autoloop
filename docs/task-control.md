# 任务控制扩展

此 Fork 基于上游 `2ee148985c8ac49069a19d13c5ba93960cd9568e`，保留 MIT 许可证。补跨规则任务身份、整体停止、重新执行、删除及任务输出读取；队列、领取、回执、重试、事件日志及进程树中止继续使用原生实现，不增加界面或新的执行器。

## 任务详情与实时输出

`GET /v1/tasks/{id}/details` 返回任务身份、当前尝试、全部执行记录、当前尝试的人工问题卡片及未触发复查数量；不返回执行令牌或规则正文。配置独占工作区的运行包含批准范围内的目录及候选证据，宿主按项目授权后显示。已删除任务只返回最小删除标识。`GET /v1/tasks?ids=a,b` 一次读取 1–50 个明确任务，缺失项不返回；二者仅接受本人密钥。

### 执行关系与真实交接

本次扩展在每条 execution 增加领取配置的岗位名称、Worker、运行程序、模型与思考强度，以及原生 session、续接来源、输入事件、已接受的输出事件、父执行编号和被拒绝的回执项。既有字段保持含义；任务之外的插件协议不变。领取配置从该执行的 rules_version 读取，不能用当前规则冒充历史配置。没有实际会话时返回 null；有续接请求不等于已经成功续接，调用方需比较请求与实际会话。

事件包含原生数字编号、来源、外部编号、类型、固定任务 subject、摘要、详情、链接、接收时间、跳数和实际 routed／paused。父执行从本任务原生 emitted 与 run_events 的交集推导；同规则同尝试的人工问题续接通过原生卡片 answer_event 回溯提问执行的业务来源，不能从模型 detail 或 subject 反查另一任务。保存的结构化事件用于显示业务通过或退回，程序 state 仍独立表达执行结果。被拒绝的事件不能标为已经交接；停止后迟到回执不会凭显示逻辑产生下一阶段。

任务详情仍是只读查询，不增加状态机、投影写入或自动派发。其证据来自既有事实，重启重建后相同；删除后不返回事件正文、岗位、会话或任何历史详情。正文输出继续按独立分页接口读取，关系查询不复制日志内容。接口只供持有本人密钥的宿主使用，由宿主重新校验业务权限。

任务 Worker 继续读取原生 `stdout-N.log`、`stderr-N.log`，通过 `POST /v1/runs/{id}/output` 携本轮令牌回传 `{turn,stream,offset,data,complete}`；data 是原始字节的规范 Base64，单段最多 64 KiB。确认前把整段写入本机恢复记录，丢应答时重发同一段，不能因文件增长改变重传内容。Hub 按执行尝试、轮次、流与字节位置去重，错误位置拒绝。每次执行尝试累计最多保存 32 MiB，超限返回明确截断及完成标记，不宣称保存了全部输出。

输出沿原生事实事务持久保存，重启重建后位置和正文一致。`GET /v1/runs/{id}/output?after=0` 仅接受本人密钥，一页最多 16 段，返回 items、next、more；下一页使用 next。正文不重复放进全局事实 SSE 或 why，消费者从独立分页口读取。浏览器不得拿到本人密钥，外部宿主须再次校验项目和轮次归属。

Worker 每轮先检查中止，再回传最多两段。进程结束后，输出有进展时连续补齐；失败恢复原生长轮询等待，避免空转。补齐后才交最终回执，故传输中断可能暂时显示等待核实，不能伪装已停止。输出在任务停止及重新执行后保留，随完整删除清理，重建不复活。不提供模型未输出的内部推理或工具没有写入 stdout/stderr 的内容。

首次创建允许可选 `stopped:true`：在同一原生事务内登记并停止任务，使离线期间已撤回的投递不会出现可领取窗口。它不参与业务输入身份哈希；重复普通创建不能解除停止，对已有任务请求 stopped 仍只针对第一次尝试，迟到请求不能停止后来尝试。旧的无 stopped 创建保持原行为。

## 重新执行与删除

`POST /v1/tasks/{id}/restart` 接受 `{request, attempt, event}`：request 是稳定请求标识，attempt 是已核实停止的当前尝试编号，event 是重新开始的可信阶段事件。相同请求同输入只创建一次新尝试，不同输入冲突。新尝试使用独立事项和会话；旧尝试保留停止记录，旧事件、回执、卡片与复查不能进入新尝试。不恢复被中断命令，不自动回滚已有代码。追加事件和停止请求必须携带当前 attempt，防止迟到请求操作新尝试。

`DELETE /v1/tasks/{id}` 请求删除整个任务，重复请求沿原删除继续；正在执行时先停止。状态为 deleting，等待全部已领取执行结束及相关 Worker 清理确认后才为 deleted。删除启动后不能重新执行或追加事件。Worker 离线、目录被占用、权限错误或路径校验失败时保持 deleting，重连重试。只有登记的 Worker 身份能确认自己的清理项。

清理对象包括任务的所有尝试、事件、轮次、卡片、投递、复查，以及 Worker 管理的轮次上下文、日志、恢复文件和工作区所有权清单登记的独占 Git worktree。规则 cwd 是提供者的原仓库，永远不递归删除；远端分支、PR 和运行程序自行保存的会话属于外部资产。未声明 workspace 的原生规则不清理其共享 cwd。

Hub 在同一事务中清理任务投影与历史事实正文，重建后不得恢复；保留最小删除标识和数字编号高水位，防止任务 ID 重用及旧执行令牌命中新任务。日志序号不重新编号，其他任务数据保持原位。已经发到外部通道或客户端的副本不属于 Hub 可撤回范围；事实流的删除记录要求消费方同步清除自己的任务投影。

## 受权配置管理

规则可以声明 `workspace: {root, ref, mode, passed?, failed?, reworkLimit?}`。cwd 为批准根目录内的 Git 仓库，root 为同一批准根目录内的任务目录，mode 为 develop、review 或 test。reworkLimit 限制自动完成开发后的返工次数，超出后用原生问题请求人明确继续；只保存已完成开发的 run 身份，技术重试不重复计数。仅任务执行使用此字段；Worker 在本机配置 roots 白名单，Hub 配置不能扩大本机授权。每个任务尝试创建独立 Git worktree，基准提交固定，目录归属清单在准备前保存；初始化失败可以沿原请求继续。

develop 的有效结果将工作区固定为 Git 候选；review 在独立只读文字快照中读 base 到 candidate 的差异，避免候选代码作为审查环境配置执行；审核或检查直接作为任务入口时，固定基准提交为初始候选；基准与候选相同时，review 复用安全 Git 调用生成空树到该提交的文本差异，candidate.json 标明 repository 范围，二进制内容不展开，不检出仓库配置。test 固定同一候选运行可信 command Agent，以实际退出码生成 passed 或 failed 事件。每次返工替换候选，后续检查重跑。测试依赖在 Worker 维护，命令未启动与正常非零退出分开报告。只读审核不能写入开发目录；权限取自 Agent 的原生访问配置。

每阶段的 context.taskRequest 同时提供本次尝试的原始需求和该轮输入事件之前的人工修改要求，均为资料而非配置指令。审核不能只依赖开发者的交接摘要。人工修改要求由本人任务事件接口标识，Agent 派生事件不能冒充；最多保留最近 20 条修改资料，并显式报告更早条目的数量。其他任务、后续新要求和其他执行尝试不会混入当前轮次。

本人主动要求修改时，当前请求就是本轮继续开发的明确授权，不再因自动返工次数重复询问。context.taskRequest.explicit 由 Hub 核对本轮输入中是否含本人请求；以前的人工修改不能替后续自动返工解除次数限制。

Worker 使用 `POST /v1/runs/{id}/evidence` 在原生 run token 范围内保存 `{directory,base,candidate,mode,command?,exitCode?}`，这是 Worker 证据，不从模型回执读取。重复相同证据幂等，不同证据拒绝覆盖。执行关系查询包含该证据。删除任务时 Worker 核对自己创建的清单与 Git 真实登记，移除全部尝试的 worktree 和快照后才确认；其他目录一律不清理。

流水线规则可声明 `expected` 为本轮互斥结果事件。Worker 在回执收尾时核对恰好一个允许的结果或提问；缺失、多个或到达跳数边界会转为原生问题卡片，保留原会话，由人回复后继续，不自动重做业务。结果事件 ID 由 Worker 按 run 与类型生成，避免模型在返工时重复使用第一次结果 ID，被原生去重静默吞掉。技术重投仍使用同一结果 ID。中心另校验终点事件才能验收。

到达 8 层边界的任务问题返回 `canRenewChain: true`。本人通过回答接口显式提交 `renewChain: true`，才允许在原任务尝试、原规则和原会话开始新的跳数预算；回答事实记录 renewedChain。通道回复、普通回答、模型回执和自动技术重试均不能重置预算。中心必须在提交前明确展示“授权继续一轮自动接力”，不能默认勾选或后台代答。

`GET /v1/configuration` 仅接受本人密钥，返回稳定实例标识、协议版本、生效配置及内容修订号。实例标识由本机随机主密钥单向派生，不包含密钥；重新初始化实例会改变身份。配置读取去掉内核自动添加的定时来源，可直接送回原生校验器。

`GET /v1/identity` 在本人授权下只读取稳定实例身份与协议版本，调用方在每次任务操作前核对，防止同一地址被新实例替换后重复派发；本机规则文件损坏不阻断此核对及停止已有任务。

revision 同时绑定原生配置事实版本和内容，hash 单独表示规范化内容。规则改动后再改回相同内容，也产生新 revision，拒绝迟到的旧发布覆盖；不能单用内容哈希作为并发条件。

`POST /v1/configuration/check` 接受 `{rules}`，只运行原生 `parseRules`，返回规范化配置和修订号，不写文件或事实。`PUT /v1/configuration` 接受 `{revision,rules}`；先核对当前修订号，再在同目录原子替换规则文件，立即沿原生 reloadRules 生效并回读。已生效的同一规范化内容重复提交返回当前结果，便于请求丢应答后核查；其他过期修订返回 409，不覆盖更新。文件写入和事实写入不声称跨介质事务，进程在二者之间退出时由启动时的原生加载恢复。管理 HTTP 和本机 CLI 不能同时改写同一配置文件。

`PUT /v1/keys/worker/{name}` 接受 `{key}`，本人授权登记调用方生成的专用 Worker 密钥，只保存哈希。同名同密钥幂等，不同密钥返回 409，不能隐式替换在线节点。接入密钥是原生长期 Worker 凭据，撤销前持续有效；一次展示不等于一次性配对。原生 `join` 和服务安装继续负责电脑接入，不另建守护程序。读取配置、节点和任务均不回传密钥或其哈希。

管理文件 I/O 在 host 层，HTTP 层只负责鉴权、大小限制和调用管理端口；内核规则校验及事实处理继续作为唯一执行来源。普通 Worker、来源及通道密钥不能调用这些管理接口。

Worker 以自己的密钥向 `POST /v1/worker/report` 报告本机批准 roots、程序检测和可用 Git 仓库；目录与模型账号只在本机检查，不从中心下发命令探测。`GET /v1/workers` 向本人返回登记、在线和报告，`PUT /v1/workers/{id}` 配置显示名称及容量。容量只限制后续领取，不能把仍在执行的进程伪装结束；本机批准目录不在远程可修改字段中。报告与心跳分别记时，在线不等于运行程序已验证。

## 身份与接口

任务管理接口仅接受本人密钥，清理确认接口仅接受所属 Worker 密钥，浏览器不持有这些密钥。调用方先核验真实项目权限；Hub 不另建账号体系。

| 请求 | 合同 |
| --- | --- |
| `POST /v1/tasks` | `{id, project, source, event}`：调用方生成全 Hub 唯一的稳定任务 ID，绑定项目标识、已配置来源和首个原生事件；同 ID 同规范化输入返回原任务，不同输入返回 409 |
| `GET /v1/tasks/{id}` | 返回固定身份、创建与停止时间、`active/stopping/stopped/deleting/deleted`、所属轮次 ID 和尚未核实结束的轮次 ID |
| `POST /v1/tasks/{id}/events` | `{attempt,event}` 提交后续外部事件，同一尝试按来源与原生事件 ID 去重；不允许复用其他任务或非任务事件的 ID；停止后返回 409 |
| `POST /v1/tasks/{id}/stop` | `{attempt}`；原子记录停止意图、取消排队、关闭待确认卡片、移除未到期复查；重复请求读取同一停止结果 |

`id`、`project` 为 1–64 位 ASCII 字母数字、点、下划线或连字符，首位字母数字。事件沿用原生长度与类型验证；任务事件的 subject 固定为任务 ID，调用方不传或必须相同。任务内事件去重同时包含执行尝试；不同任务仍不得占用同一来源事件 ID。中心应给事件 ID 加任务前缀。派生事件的 task_id 从父轮次继承，subject 被归一到任务 ID；模型不能借回执指向另一任务。内部事项使用不能从外部 subject 输入的独立命名空间，不与普通事件合并，即使规则没有 parallel 也不合并不同任务。

任务 ID 与原生 run ID、event ID、card ID 分开；task_id 随事实日志保存，查询与重建使用同一投影。原生状态中的轮次、卡片和复查增加可选 taskId，普通任务不增加此字段。项目标识是可信调用方登记的归属，不由模型正文推断。模板、目录、程序和权限仍只由可信规则配置。active 只代表当前尝试可继续接收事件，不代表业务完成；重新执行保留 task_attempts 的旧停止记录，当前任务指向新的尝试。轮次、卡片和复查沿用独立尝试身份。

## 停止与核实

停止和并发回执在原生事实事务中串行裁决。回执先到，停止覆盖其已派生阶段；停止先到，回执仍保留 outcome、summary、error、session 和 usage，但 ask、notice、resolve、later、events 均不生效，不重试。实际成功退出可保留 done，不把已经完成的工作伪造为取消；任务整体为 stopped。

所有 claimed 和 unknown 轮次持续列入原生 Worker 的 cancel 列表；Worker 确认进程树结束后提交原生结果。只要还有其中任一轮次，任务就是 stopping，包括 Worker 离线、漏报执行或重启。只凭超时、缺少心跳、删除规则或收到停止 HTTP 应答不能宣称结束。Worker 丢失本机执行记录时仍等待核实，本批没有强制标记停止入口。

任务使用本 Fork 的配套 Worker：保留原生执行器，修正领取响应同时带取消时不启动、启动前重启先核对停止，以及无法检查进程时保留停止记录继续检查。停止核实先于插件加载；插件失效不能跳过退出核实。取消优先于超时和回执收尾，保留原停止宽限期，不再启动回执修复。未升级的上游 Worker 不能视为已满足完整停止合同。派生事件 ID 与其他任务冲突时仅 rejected 该事件，不拒收整份退出证据。

停止不回滚代码或外部副作用，不清理工作目录。任务之外的事件与规则保持原生行为。删除按上述两阶段合同执行；任务 ID 和原事件 ID 哈希墓碑保留，拒绝迟到重放。

Worker 从原生 `GET /v1/work` 的可选 cleanup 数组取得任务及数字 run/attempt 清理清单，清理后调用 `POST /v1/tasks/{id}/cleanup`。清单来自全部历史领取者，不依赖当前规则指向的 Worker；旧 Worker 不确认清理时任务持续 deleting。Worker 的上下文、日志和任务独占用量缓存被清除，使用哈希目录名避免 Windows 大小写及设备名冲突。

这是配套 Hub、Worker 与服务端客户端的协议更新：原停止空对象和直接追加事件请求需要改为带 attempt 的对象。验证从全新隔离数据开始，旧实验 Fork 的任务缺少尝试及领取归属，不支持把旧实验数据原地升级后当作已满足完整删除。无任务扩展的原生事件与插件保持不变。删除清除可查询的数据库正文和所属文件，不承诺覆盖磁盘取证、外部备份或已经交付给其他系统的副本。

## 维护与验证

上游为 upstream，本 Fork 为 origin；开发使用 codex/task-lifecycle worktree，不跟随上游未验证的新提交。扩展使用零运行时依赖、原生 HTTP 客户端及事实日志。新增代码注释和提交信息使用简体中文，优先于上游注释语言约定。

回归覆盖排队、执行、重试、卡片、复查、跨规则派生、未知执行、重复停止、身份冲突、错误密钥、重放及原生 Worker 进程树停止。输出另验真实 HTTP/子进程、大文件分页、丢应答补传、Hub/Worker 重启及删除重建。隔离验证使用临时目录、回环接口和虚构任务；真实 Codex 验收使用提供者已有登录，只操作隔离样例，不复制中心模型密钥、不调用生产业务服务。
